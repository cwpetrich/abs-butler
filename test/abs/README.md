# A disposable AudiobookShelf to develop against

`normalize --apply` rewrites titles and authors and `organize --apply` moves files, so both need
somewhere to be wrong without it mattering. This is that somewhere: a throwaway AudiobookShelf with
a library that is messy on purpose, rebuildable in about a minute.

```bash
docker compose up -d
node seed.mjs        # 16 books of generated silence
node bootstrap.mjs   # root user, library, scan, and the intended mess
```

Then point abs-butler at it, with its own database so your real one is untouched:

```bash
export BUTLER_DATA_DIR=$PWD/butler-data
node ../../dist/index.js connect \
  --url http://127.0.0.1:13377 \
  --api-key "$(cat .token)" \
  --library-root "$PWD/library"

node ../../dist/index.js normalize          # dry run
node ../../dist/index.js configure --metadata-rewrite on
node ../../dist/index.js normalize --apply
node bootstrap.mjs                          # put the mess back, ready to go again
```

Server on <http://localhost:13377>, root / `buttertest`. Port 13377 stays clear of 13378 and 13379
(other local AudiobookShelf instances) and 13380 (abs-butler itself).

## Reaching it from elsewhere

The container binds to localhost only. For access from your other devices, Tailscale proxies it:

```bash
tailscale serve --bg --https=13377 http://127.0.0.1:13377
# https://<your-machine>.<tailnet>.ts.net:13377
tailscale serve --https=13377 off      # to undo
```

**Tailnet only — do not add `--funnel`.** Funnel puts a listener on the public internet, and this
server has a throwaway password by design. Nothing here is worth reaching from outside your tailnet.

## No audio is downloaded

Every book is two seconds of silence generated by the ffmpeg inside the AudiobookShelf image. The
books themselves are real, and mostly public domain, because the providers have to be able to find
them — a library of invented titles would exercise the plumbing and none of the matching. What is
being tested is metadata, and a real audiobook is a gigabyte of nothing useful to that.

The one exception is the Harry Potter row, which exists to carry a real Audible ASIN so the Audnexus
provider tier fires at all. It is a catalogue identifier against two seconds of silence.

## Why the mess is applied after the scan

AudiobookShelf tidies some of it during a scan — hand it an `artist` tag of "Stoker, Bram" and the
scanned item comes back as "Bram Stoker". A library seeded purely from audio tags therefore arrives
already half-fixed, and the cases abs-butler exists to repair never appear.

So `bootstrap.mjs` writes the intended state over the scan through the API. That is also closer to
how libraries really go wrong: an import, another tool, or a hand edit, long after the scan.

## Things this environment has already caught

Kept because each one only appears against a real server, and each is a regression worth noticing if
it comes back.

- **The library listing is minified.** `/api/libraries/:id/items` omits `authors`, `narrators` and
  `series` entirely — it carries only the flattened `authorName`, `narratorName` and `seriesName`.
  `organize` read series from there, so every book in a series planned a move to `Author/Title`,
  lifting it out of its series folder on apply. Both commands now fetch expanded items.
- **`updateAuthorsFromRequest` replaces the whole list.** Anything the patch does not mention is
  deleted, so a one-author proposal removed a co-author. The Gilded Age is the fixture for it.
- **A case-only rename of an author or series cannot be applied.** ABS resolves both to records by
  name, case-insensitively, so the write is accepted and changes nothing — and would be proposed
  again forever. `Warlord of Mars` carries `barsoom` as the fixture; normalize deliberately proposes
  nothing for it.

## Starting over

```bash
node bootstrap.mjs                                    # just re-apply the mess
docker compose down && rm -rf config metadata library .token butler-data
```

The full reset is needed whenever `seed.mjs` changes an audio tag: AudiobookShelf does not re-read
tags for items it has already scanned, so the old titles would survive a rescan.
